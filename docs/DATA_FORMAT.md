# `data/mpls_graph.js` format (version 1)

Generated by `tools/build_osm.py`. The file assigns one object to `window.MPLS_GRAPH`, so pages
load it with a plain `<script src>` (works from `file://` and GitHub Pages; no fetch, no build step).
Street data © OpenStreetMap contributors, ODbL.

## Coordinates

- Local equirectangular projection of the bounding box. **x points east, y points south**
  (canvas convention); the origin is the box's north-west corner.
- All coordinates and lengths are **integers in units of 1/`unitsPerMeter` m** (decimeters).
  Divide by `unitsPerMeter` to get meters.
- Nodes outside the box never appear; roads that cross the edge end at **portal** nodes on it.

## Top level

| Key | Meaning |
|---|---|
| `v` | Format version (1) |
| `label` | Human-readable description of the area |
| `attribution` | Required credit line |
| `bbox` | `[south, west, north, east]` in degrees |
| `size` | `[width, height]` of the box in units |
| `unitsPerMeter` | 10 |
| `classes` | Road class names; links store an index into this list |
| `names` | String table for street names (`0` = unnamed) |
| `nodes` | Columnar node arrays (below) |
| `controllers` | Signal controllers (below) |
| `links` | Columnar link arrays (below) |
| `shapes` | Flat, delta-encoded interior geometry for all links |

## Nodes (`nodes.x[i]`, `nodes.y[i]`, `nodes.flags[i]`, `nodes.ctl[i]`)

Topological nodes only: intersections, dead ends, portals, signal and stop-sign nodes.

| `flags` bit | Meaning |
|---|---|
| 1 | Portal: the road continues off-map |
| 2 | Signalized: belongs to controller `ctl[i]` |

`ctl[i]` is the controller index, or −1.

## Controllers (`controllers.axis[c]`)

Signal nodes within 30 m of each other form one controller (dual-carriageway crossings, signals
mapped on approaches). `axis` is the orientation of the crossing in degrees modulo 90. Each
approach is assigned phase group 0 (within 45° of the axis, mod 180) or 1 (the cross street).

## Links (`links.<column>[j]`)

A link joins two topological nodes, `a` → `b` in OpenStreetMap way order, and carries the street's
geometry between them. Two-way streets are one link.

| Column | Meaning |
|---|---|
| `a`, `b` | Node indices |
| `dir` | Bitmask: 1 = general traffic a→b, 2 = general b→a, 4 = shuttles/buses only a→b, 8 = shuttles/buses only b→a |
| `kph` | Speed limit (OSM `maxspeed`, else class default), km/h |
| `lf`, `lb` | Lanes in the a→b and b→a directions |
| `cls` | Index into `classes` |
| `flags` | 1 = bridge, 2 = tunnel, 4 = stop when arriving at `a` (travelling b→a), 8 = stop when arriving at `b` |
| `name` | Index into `names` |
| `sigA`, `sigB` | Signal phase group on arrival at `a` / `b`: −1 none, 0 or 1 phase group, 2 inside a controller cluster (never stops) |
| `len` | Length along the geometry, units |
| `way` | Source OSM way id (`https://www.openstreetmap.org/way/<id>`) |
| `shp` | Number of interior shape points this link takes from `shapes` |

### Geometry

Links are stored in order. For link *j*, start at node `a`'s coordinates and read `shp[j]` pairs
`(dx, dy)` from `shapes`, continuing where link *j − 1* stopped; each pair is added to the
previous point. Finish with node `b`. A link with `shp = 0` is a straight segment.

`src/graph.js` (`decodeMplsGraph`) performs this decoding and builds directed adjacency lists.

## Validation report (`data/mpls_graph.report.json`)

Counts, km by class, portals (entry/exit, position, road), bridges and shuttle-only streets by
name with lengths, signal controllers, stop approaches, ways skipped and why, and what
connectivity pruning removed. Review it after every rebuild.

# `data/mpls_demand.js` format (version 1)

Generated by `tools/build_demand.py`; assigns one object to `window.MPLS_DEMAND`. Census data
(2020 Census blocks via TIGERweb; LEHD LODES 8 WAC and OD) is public domain; parking comes from
OpenStreetMap (ODbL). Coordinates are **meters** in the same projection as the street graph
(x east, y south, origin at the box's north-west corner), rounded to whole meters.
`src/demand.js` (`createDemand`) reads it and generates the day's trips.

| Key | Meaning |
|---|---|
| `v` | Format version (1) |
| `sources` | `{ census: 2020, lodes: <year> }` |
| `bbox` | `[south, west, north, east]`, as the street graph |
| `zones` | Columnar arrays, one entry per census block inside the box with residents, jobs or out-commuters |
| `internalOD` | `[homeZone, workZone, workers]`: commutes with both ends in the box (LODES OD, all jobs) |
| `inboundBySector` | Jobs in the box held by people living outside, by home direction: 16 compass sectors of 22.5°, sector 0 centred on north, clockwise, seen from the box centre (home tract centroids; out-of-state homes by state) |
| `outboundBySector` | Residents of the box working outside, by work direction |
| `campus` | UMN East and West Bank: name, lat/lon, x/y, radius (m), share of students |
| `campusStudents`, `campusLiveInBox` | Students on the Minneapolis campus on a typical weekday, and the share living inside the box (assumptions, see PLAN.md Phase 5) |
| `hospitals` | Sites whose health-care jobs (within the radius) follow shift changes |
| `venues` | Stadiums and arenas with capacities, for event surges |
| `parking` | Ramps and lots: name, `kind` (OSM `parking=*`), x/y, `capacity` (OSM tag, else estimated from footprint × levels ÷ 28 m²), `estimated` |

## Zones (`zones.<column>[i]`)

| Column | Meaning |
|---|---|
| `x`, `y` | Block internal point |
| `pop`, `hu` | 2020 Census population and housing units |
| `jobs` | LODES jobs (all, JT00 S000) |
| `office`, `retail`, `food`, `health`, `edu` | Jobs in NAICS groups: office = information, finance, real estate, professional, management, administrative, public administration (hybrid work applies); retail; accommodation and food; health care; education |
| `inbound` | Of `jobs`, held by people living outside the box |
| `outbound` | Residents working outside the box |

## Report (`data/mpls_demand.report.json`)

Totals (residents, housing units, jobs by group), commuters (internal, inbound, outbound; OD vs
WAC check), commuters by direction, the downtown subset (Downtown West and East, North Loop,
Loring Park, Elliot Park, approximate outline), parking facilities and spaces, warnings.

# `data/mpls_buildings.js` format (version 1)

Generated by `tools/build_buildings.py`; assigns one object to `window.MPLS_BUILDINGS` (loaded
by the page after start). Building data © OpenStreetMap contributors, ODbL. Same projection as
the street graph (x east, y south, meters from the box's north-west corner).
`src/buildings.js` (`decodeBuildings`) decodes it.

| Key | Meaning |
|---|---|
| `v` | Format version (1) |
| `unit` | Meters per stored coordinate unit (0.5) |
| `kinds` | Building kinds (house, apartments, commercial, office, university, civic, industrial, garage, parking, stadium, church, other); `buildings.k` indexes it |
| `names` | String table (`0` = unnamed) |
| `buildings` | Columnar: `n` points, `h` height and `mh` minimum height (decimeters), `k` kind, `name`, `x0`/`y0` first point (units) |
| `pts` | For each building in order, `n − 1` delta pairs `(dx, dy)` in units from the previous point |

Rings are the outer outline only (courtyards are filled), simplified (Douglas–Peucker 0.6 m),
stored with positive signed area in x-east/y-south coordinates. Buildings are kept when their
centroid is inside the box. OSM `building:part` ways replace the outline they sit in (Simple 3D
Buildings), except for the landmark outlines that have hand-built designs. Height: `height`
tag, else `building:levels` × 3.3 m (+ half the roof levels), else a short list of known towers,
else a default by kind. The report lists counts by height source, what was dropped and why, the
tallest buildings and the landmarks found.
